# MemoryLake use cases

Runnable demos for the use cases on [memorylake.ai/usecase](https://www.memorylake.ai/en/usecase).
Each directory is one use case, built on the [`memorylake` CLI](https://github.com/memorylake-ai/memorylake-cli),
and runs end to end with nothing more than a MemoryLake API key.

| Use case | Audience | What it shows | Time | Demo videos |
|---|---|---|---|---|
| [sales-call-memory](sales-call-memory/) | Sales & revenue teams | Call transcripts → extracted, dated facts; rep notes pinned as facts; hand-off docs as documents; a CSM brief generated by searching the account memory. CLI runner plus a local web UI (`python3 web/server.py`) | ~3 min | [CLI 4:12](https://github.com/memorylake-ai/memorylake-usecases/releases/download/sales-call-memory-v1/sales-call-memory-cli-demo.mp4) · [Web 4:59](https://github.com/memorylake-ai/memorylake-usecases/releases/download/sales-call-memory-v1/sales-call-memory-web-demo.mp4) |
| [chatbot-user-memory](chatbot-user-memory/) | Engineering & developers | Per-user memory for a chatbot: sessions as user↔bot conversations, facts owned by the user's actor, one scoped search per turn as the model's memory block, cross-user isolation check, right-to-be-forgotten via `fact delete`. CLI runner plus a local web UI | ~2 min | [CLI 2:40](https://github.com/memorylake-ai/memorylake-usecases/releases/download/chatbot-user-memory-v1/chatbot-user-memory-cli-demo.mp4) · [Web 2:49](https://github.com/memorylake-ai/memorylake-usecases/releases/download/chatbot-user-memory-v1/chatbot-user-memory-web-demo.mp4) |

## Before you start

1. **Get an API key.** Sign up at [app.memorylake.ai](https://app.memorylake.ai), open **API Keys**
   in the sidebar, create a key and copy it. See [Authentication and API Keys](https://docs.memorylake.ai/authentication).
   A free personal account is enough for every demo here unless its README says otherwise.
2. **Install the CLI.**

   ```bash
   # macOS / Linux
   curl -fsSL https://raw.githubusercontent.com/memorylake-ai/memorylake-cli/main/scripts/install.sh | sh
   ```

   ```powershell
   # Windows
   irm https://raw.githubusercontent.com/memorylake-ai/memorylake-cli/main/scripts/install.ps1 | iex
   ```

3. **Run a demo.**

   ```bash
   git clone https://github.com/memorylake-ai/memorylake-usecases.git
   cd memorylake-usecases/sales-call-memory
   export MEMORYLAKE_API_KEY=sk-…
   python3 demo.py
   ```

Every demo reads the key from `MEMORYLAKE_API_KEY` and logs into its own CLI profile inside the demo
directory, so your existing `memorylake auth login` session is never touched. Leave the variable unset
to use that session instead. `MEMORYLAKE_BASE_URL` switches endpoints: the China deployment is
`https://app.memorylake.cn/openapi/memorylake`, and accounts there are separate from the global ones.

## Conventions for a use case directory

If you add one, keep it self-contained and honest about what it needs:

- `README.md` links the use case page it implements, states the prerequisites (an API key, the CLI,
  and nothing else unless unavoidable), and walks through the CLI commands the demo runs.
- One entry point (`demo.py`, `run.sh`, …) that prints every `memorylake` command before running it.
  Readers should be able to copy any line into their shell.
- Sample data lives in `data/`, generated output in `out/` (git-ignored). Data is fictional.
- Everything the demo creates carries a `custom_id` with a unique prefix (`mlu-<usecase>-…`), is found
  again by that id on re-runs, and can be removed with a `cleanup` command.
- Credentials come from `MEMORYLAKE_API_KEY` and go into an isolated `MEMORYLAKE_CONFIG_DIR` under the
  demo directory, never into the user's home config.
- If a step needs something a free account does not have (model quota for agents, for example), make it
  optional and say so.
- A web UI is welcome but optional. If you add one, keep it dependency-free (the sales-call-memory
  one is a standard-library HTTP server plus static files), bind it to localhost, and drive the same
  code path as the CLI runner so the two never drift.
